| 工程模块                  | 框架负责固定什么                                                                 | 每个项目自行定义什么                                                  |
| --------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------- |
| **1. 数据契约**           | 时间、品种、OHLCV、交易日、session、合约信息的标准 schema；数据校验与频率适配                         | 原始数据来源、分钟线、Tick、Level2 等具体适配器                               |
| **2. 市场时间管理**         | 统一时间索引、时区、交易日与 session 标识；提供可配置的窗口边界策略，支持禁止跨越、允许跨越或在边界处裁剪                | 市场日历、交易时段，以及具体任务是否允许跨 session、跨交易日                          |
| **3. Event Selector** | 统一的事件候选输出格式和调用接口；保证只使用事件时点之前的数据                                          | 如何识别事件、使用什么窗口、阈值、去重和聚类规则                                    |
| **4. 事件对象**           | 标准化保存 `decision_time`、可选的 `direction`、`score`、`metadata`                 | 项目需要附加的 selector 信息，以及是否需要方向字段                              |
| **5. 方向统一**           | 提供可选的方向标准化组件和统一转换接口；未启用时保留原始坐标，其他模块不得强制依赖方向统一结果                          | 是否启用方向统一、方向定义，以及哪些变量需要方向化、哪些保留原始值                           |
| **6. 特征计算**           | 因果窗口、特征注册、批量计算、训练和推理一致性、缺失值检查                                            | 具体价格路径、成交量、波动率或盘口特征                                         |
| **7. 标签引擎**           | 根据事件后的路径生成标签；支持 horizon、barrier、timeout、first-touch 等通用机制                | 障碍大小、时间长度、二分类/三分类/连续目标                                      |
| **8. 数据集构建**          | event、feature、label 的身份关联；时间切分；DEV、validation、holdout 隔离                 | 每个实验使用哪些事件、特征和标签                                            |
| **9. 模型适配层**          | 统一 `fit / predict / predict_proba / save / load` 接口                      | LightGBM、XGBoost、线性模型或其他 learner                            |
| **10. 决策策略 Gate**     | 将模型输出转换成 `long / short / abstain`；保存冻结规则                                 | 使用 argmax、概率差、utility、阈值或多阶段 gate                           |
| **11. 执行与回测**         | 信号到订单、持仓状态、交易成本、PnL、审计日志的基本框架                                            | 入场、止损、止盈、trailing、反向平仓、仓位规则                                 |
| **12. 运行配置与产物接口**     | 提供轻量的配置读取、结果保存和模型序列化接口；不建设独立的实验管理系统，也不规定统一实验目录                           | 在项目自己的 config、Python 文件或 notebook 中管理具体参数，并决定保存哪些模型、指标和中间结果 |
| **13. 框架级质量保证**       | 只提供可以跨项目复用的基础测试，例如 schema、接口契约、时间因果性、序列化和 synthetic smoke test；不测试具体研究结论 | 项目内部负责 selector、feature、label、gate、backtest 联动测试和业务断言       |
| **14. 框架文档与使用示例**     | 为抽象框架提供 README、接口说明和 alpha001 的完整使用示例；不强制未来项目遵循固定 notebook、CLI 或目录模板     | 每个项目根据实际研究阶段决定目录、notebook、脚本、CLI 和报告形式                      |
