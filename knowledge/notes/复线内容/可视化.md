# 可迁移版可视化 App 实现 Prompt

> 用途：把这份文件整体交给另一台机器上的 AI coding agent，要求它在新的项目目录中复刻当前的研究可视化 App。
> 所有路径、端口、域名、数据规模和具体数值都使用占位符；不要把本机环境值写死。

## 1. 角色与目标

你是一名熟悉 Python 数据工程、原生 HTML/CSS/JavaScript、Canvas 交互和量化研究数据语义的全栈工程师。

请在以下占位项目中实现一个研究型可视化 Web App：

```text
项目根目录: <PROJECT_ROOT>
前端目录: <APP_DIR>
研究输出目录: <CURRENT_ALPHA_OUTPUT_DIR>
旧版独立输出目录: <LEGACY_ALPHA_OUTPUT_DIR>
快照数据: <SNAPSHOT_PARQUET>
成交数据: <TRADE_PARQUET>
后端监听地址: <BIND_HOST>
后端端口: <BACKEND_PORT>
外部访问地址: <PUBLIC_URL>
````

目标不是制作营销 Dashboard，而是制作一个可以检查数据定义、盘口路径、策略信号和执行结果的研究工具。界面应优先保证：

1. 每个字段的经济语义清楚；
    
2. 事实、盘口状态和派生变量不混淆；
    
3. 所有图表交互可追溯到原始数据；
    
4. 当前版本与 legacy 版本的逻辑、数据源、政策和曲线严格隔离；
    
5. 数据替换后不需要改前端代码即可重新加载。

## 7. 数据处理规则

### 7.1 盘口基础状态

```text
valid_quote = bid_price_1 > 0 and ask_price_1 > 0
mid = (bid_price_1 + ask_price_1) / 2
spread_tick = (ask_price_1 - bid_price_1) / <TICK_SIZE>
bid_depth = sum(bid_volume_1..bid_volume_N)
ask_depth = sum(ask_volume_1..ask_volume_N)
imbalance = (bid_depth - ask_depth) / (bid_depth + ask_depth)
microprice = weighted L1 quote using bid_volume_1 / ask_volume_1
````

无效分母返回 `null`, 不要用极端数或静默的 0 替代。

### 7.2 时间聚合

每个时间层必须声明:

Plaintext

```
source frequency: <SOURCE_FREQUENCY>
target frequency: <TARGET_FREQUENCY>
state operator: last / as-of / median
flow operator: sum
bar operator: OHLC
missingness rule: <MISSINGNESS_RULE>
session boundary: <SESSION_BOUNDARY_RULE>
```

未来收益或响应必须在同一交易日、同一 session 内按目标时间做 as-of 对齐, 不能用行偏移假装秒数。

## 8. 实现限制与安全边界

- 不要删除用户已有数据;
- 不要覆盖没有确认的研究输出;
- 不要把 current 和 legacy 因子通过同名 `factor_id` 合并;
- 不要把 quote state 解释成 executed trade;
- 不要把 `open_close` 整数编码当连续变量平均;
- 不要用未来字段构造 Entry Example;
- 不要用虚构的零 PnL 曲线填补缺失的逐日数据;
- 所有外部路径、域名、端口和数值必须来自配置或环境变量;
- 页面修改后提供最小验证步骤;
- 服务停止、重启或 kill 前, 先确认目标 PID 和监听端口。
