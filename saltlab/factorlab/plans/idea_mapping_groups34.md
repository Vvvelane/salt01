# 附录：研究组 3、4 的 31 个 idea 如何变成可检验对象

本附录逐项审阅 [研究组 3](../factor_research_group3_cross_section_term_structure.md) 和 [研究组 4](../factor_research_group4_relative_value_calendar_intraday.md)。执行优先级与正式首批窗口以 [总计划](../因子研究与组合框架实施计划.md) 和 [首批实验规格](first_experiment_specs.md) 为准；本表其余窗口只列后续候选，不自动加入本轮搜索。保留经济问题，重新限定信号、预测对象和真实交易表达。它是设计与预注册草案，不是已经跑出的研究结论；旧文中的论文归因仍须按主计划的来源审计核对，不能因旧文带链接便视为完成复现。

**以下所有窗口、阈值、最小样本数、持有期、更新频率和优先级都是待检验的预注册起点，不是经验最优值或盈利保证。** 每个 idea 先选一个 primary 版本，其他版本进入登记过的诊断或扩展；禁止把表内所有数字做笛卡尔积搜索。用户假设分钟及以上价格数据充足，本附录不检查数据量；合约身份、时间戳语义、历史交易日历和交易规格属于正确实现的定义工作。

## 1. 读表约定

- `alpha`：预测可成交区间收益的候选，只有样本外净收益通过检验后才获得组合预算。
- `state`：解释当前环境；不能因值正负直接给方向仓位。
- `risk`：控制规模、尾部或暴露；效果通过组合风险及机会成本检验。
- `execution`：影响可交易性、成交时间和容量；它本身通常不产生方向。
- `formation` 是信号使用的历史长度，`holding` 是持仓时间，`rebalance` 是重新分配头寸的频率。这三个量必须分别保存。
- `P0` 是基础合同、risk/execution 共同能力；`P1` 是正式首批 alpha（含慢趋势对照）；`P2` 是后续研究，观察组优先级更低但不另设额外编号。P0 不表示先把该变量当 alpha 交易。
- 问题分类：**实现错误**是定义、因果顺序、计量单位或真实记账不成立；**假设迁移**是逻辑可能成立但证据不能直接移用；**待定细节**是旧文存在多个相互不完全一致的版本，需冻结一个口径。不能把“未被证实赚钱”直接叫作 bug。

## 4. 必须在实现前修正的共用细节

### 4.1 分开三个问题：因子值、预测标签、可执行 PnL

1. `feature_value` 只描述决策时可知的信息，例如 carry、首段收益、残差或 skew。
2. `label` 描述该经济假说指向的**未来可交易区间**，保存入场时间、退出时间及合约集合。例如尾盘因子的目标是尾盘区间，月度 carry 的目标是未来月度持有收益。
3. `orders/fills/positions/pnl` 记录具体合约和整数手数。市场没成交，不能因为理论 label 好看就记作成交；发生涨跌停不能用信号反向把仓位清零。

对于同一固定数量、已完整开平的期货头寸，可以使用以下两种等价口径；动态数量账户仍按每次真实 fill 和持仓变化逐笔记账：

```text
# 口径 A：成交价已经包含滑点、冲击与执行延迟的结果
leg_fill_pnl = signed_contracts × contract_multiplier × (exit_fill − entry_fill)
portfolio_net_pnl = sum(leg_fill_pnl) − fees

# 口径 B：使用事前定义的参考价，通过 execution shortfall 连接到真实成交
leg_reference_pnl = signed_contracts × contract_multiplier × (exit_reference − entry_reference)
implementation_shortfall = sum(leg_reference_pnl − leg_fill_pnl)
portfolio_net_pnl = sum(leg_reference_pnl) − implementation_shortfall − fees
```

两种口径必须对账一致。使用 fill-price PnL 后不能再扣一次已经进入成交价的 slippage；`fees` 包含已登记的显式收费，各收费项只入账一次。无法成交的订单不能凭参考价虚构 fill；上述两口径比较仅针对相同实际成交数量，未成交机会成本作为单独执行诊断。

每日盯市、盘中浮盈亏和现金/保证金变动另行对账，不能把保证金当作期货本金计算可跨品种比较的收益率。标准账户日收益的分母为日初资金 NAV；有外部现金流时按已声明规则调整。CAGR 从资金 NAV 权益曲线计算。`PnL/风险预算` 或单位风险 PnL 仅是另列的风险归一化诊断，不是资金收益率，不能据此计算或标注 CAGR；同时报告保证金占用和名义敞口。

### 4.2 carry 不是双腿收敛利润，也不是换仓当天的白得价差

如果当日近月 100、远月 98，正 carry 可以是看多该商品未来相对收益的 predictor；它不等于“今天买 100 卖 98 就已赚 2”。单腿持有策略的利润来自所持合约后续价格变化，换仓包含平旧、开新及成本；跨期策略另有一多一空两腿。

`FCA001/002/003` 静态版和 `FCA005` 的主研究可用曲线作预测变量、交易每品种选定单合约；`FCA006/007` 与 `FRL` 预测的是相对价值，则必须有真实多腿 PnL。两类结果不放入同一目标列后混合 rank IC。

远月可能成交稀疏，同日两个 close 并不保证是同一时点的可交易价格；日线曲线需记录估值字段及公布时间，分钟跨期需同一快照时钟与滞后/缺失标记。结算价何时公布与能否按该价成交是两件事。

### 4.3 beta、中性权重和合约手数不能混为一谈

对 log-price 残差 `e = log(P_A) − β log(P_B) − a`，若以 A 腿价值 K 建仓，近似匹配残差变化的初始数量为：

```text
q_A = K / (M_A × P_A)
q_B = −β × K / (M_B × P_B)
```

这是局部价值敏感度映射；实际必须整数化并用价格差逐腿算 PnL。固定 β 不等于固定手数后始终价值中性；若要动态维持价值比，调仓交易也要付成本。主版本建议入场固定数量、监测漂移，避免把每天重新估 beta 的纸面 residual 当作可自融资交易收益。

若回归直接用价格水平 `P_A − β P_B`，在单位转换正确的前提下，手数关系是 `q_B = −β × M_A / M_B × q_A`；不能套用 log-price 公式。产业链实物配比又是第三种 hedge 目标，必须先统一物理单位再换成合约手数。

不等期限的三腿 log-price 蝶式可以用价值敏感度系数：

```text
a1 = τ3 − τ2
a2 = −(τ3 − τ1)
a3 = τ2 − τ1
# sum(a_j) = 0；sum(a_j × τ_j) = 0
q_j ∝ a_j / (M_j × P_j)
```

该约束仅消除所定义 log 曲线的局部 level/slope 敏感度，不消除所有市场 beta、季节性或整数化风险。`[1,-2,1]` 只在等距期限、正确单位与价值映射下有对应意义。

### 4.4 协整、rolling 与品种关系的状态要可审计

- 预先给产业关系白名单，不能从所有品种两两配对后只展示成功者。记录被检验和被拒绝的每个 pair；对同一训练窗多个 pair 的检验做多重比较控制。
- 在训练期声明价格还是 log 价格、截距/趋势、滞后选择和整合阶数诊断。Python 的协整检验应使用适合估计残差的临界值（如 `statsmodels.tsa.stattools.coint` 所实现的方法），不能把普通 ADF 的 p 值直接冒充协整 p 值。
- `fit_end < first_trade_time`；冻结 beta、均值、尺度和候选集合的版本。交易期若要更新均值，必须另登记动态估计策略，因为移动的均值可以让 z “收敛”而头寸仍亏钱。
- 半衰期估计只用过去残差，报告不稳定和不可定义值；设定最大持有期的经济理由与成本检查，不能仅因拟合出短半衰期就自动建立日内策略。
- 合约滚动会改变实际腿的身份。可选择“固定 pair，临近交割退出”或“明确 roll schedule，平旧开新并重新初始化/迁移模型”，不能悄悄把新合约价格接上旧均衡关系。

### 4.5 多腿无法保证原子成交，必须保留失败过程

旧文多处的“任一腿失败全部取消”仅能描述**提交前**发现任一腿不可用便不提交，或未成交剩余订单的取消；已经成交的腿不会因为另一腿失败而从历史中消失。

实现时区分 `planned → submitted → partially_filled → hedged / cancelled_remainder / unwinding → closed`。在只有 1 分钟 OHLCV 时，先做保守批次成交：订单在 bar 前已提交、下一 bar 有效且满足预先冻结的可交易规则才成交；任一腿无法成交则记录已暴露腿和预先声明的撤余单、下一可交易点平仓流程。压力测试增加一腿延迟和额外成本。若假设全部腿同时成交，报告标题必须明确这是理想成交上界，不能当实盘可实现性证据。

止损同样如此：价格触及不代表按止损价成交；1 分钟 OHLC 不知道先碰止盈还是止损。首批日内基准使用计划退出和组合风险限制，减少路径假设。随后增加止损时，采用可复核的保守顺序及缺口成交规则；不同规则的净值差应单独展示。

### 4.6 日内 signal availability 的一分钟边界示例

以仅用于说明的日盘 09:00–15:00 为例，真实实施要按品种和日期的 session map，不把例子写死到所有合约：

1. bar 必须统一表示 `[bar_start, bar_end)`；`C` 是该区间末的已知成交价。另存 `available_at`，显式包含处理/供应延迟。
2. 首段指标到 09:30 才形成，E01 可以提前生成 14:30 entry、14:55 exit 的时间订单；正常持有 25 个可交易分钟。09:30 信号不能包含随后 bar，实际边界由品种历史日历生成。
3. 首批 FID003 只提供 E01 的反转竞争解释，不另开一套尾盘前累计收益策略。后续若注册这种 predictor，使用截至 14:30 的行情时，`available_at` 不能早于 14:30；即时入场须满足 `bar_start > decision_ready_at`。实际 holding 由正式预定 entry/exit 及延迟决定；若退出仍为 14:55，延迟入场就短于 E01 的 25 分钟，不写死为 29 分钟。
4. “最后 30 个交易分钟”与“墙钟 30 分钟”在休市、分段盘或不同夜盘结束时间下可能不等价。截面排序只能比较同一时点已知数据，不能为了让篮子整齐而使用较晚收盘品种的未来数据。
5. 正式首批预定退出 X 是日盘收盘前第 5 个交易分钟的 start；无法成交时继续记账和执行减仓，保留被动隔夜风险与违例事件，不能假装已平仓。
6. FID001/FID003 首批只有 E01 一个目标头寸。以后 FID002 或其他候选通过增量检验获准加入时，同一合约目标先净额合成，再执行真实变动；研究账保留归因，账户账只保留真实净合约与费用分摊。

### 4.7 接入正式首批及后续候选产出

1. 建立 `hypothesis_registry`：每个 source ID 一行，另用 experiment→source 映射表实现去重；保存 role、family、primary horizon、source status、expected sign、decision clock、entry lag、exit clock 和试验总数。一个 ID 不自动等于一个获得资本的实验。
2. **正式首批统一为** `OPEN_TO_TAIL_V1`、`ORB_CONT_V1`、`PRESSURE_REV_V1`、`DAILY_TREND_V1`；共同组件为 `RV_SCALE_V1`、`ACTIVITY_STATE_V1`。全部具体规则只引用 [首批实验规格](first_experiment_specs.md)，本附录不增加首批实验。组 3/4 贡献的是 E01 的 FID001/FID003 解释和 E02 的 FID004；E03/E04 的源 idea 在组 1/2，不能因本附录范围较小将它们遗漏。
3. P0 层处理 FCS003 涉及的可执行性/容量合同，以及 FSE003 所依赖的交易日历/时钟；先产出成交失败原因、成本、持仓与资金对账。星期收益统计、高 ILLIQ 溢价等仍是 P2 后续假说，不能偷渡成首批过滤器。
4. 首批完成后，先按正式 C01/C02 输出固定 alpha 的风险缩放消融、活动状态分组，之后才讨论过滤版本。FID002、FCM004、FOT001/002/003 均是 P2 增量候选；每次只增加已注册的条件变量，报告加入前后的样本外收益、风险、成本与负面结果。
5. 后续研究 `FCM001/002/003` 和 `FCA001` 的日/周/月 sleeve，与已经存在的 E04 慢趋势对照及日内 sleeve 比较相关性、风险贡献和资金占用；它们不取代或扩充正式首批。这解决“全仓头寸平衡”问题，不要求每个经济 idea 都变成日内 alpha。
6. 多腿状态机通过可审计的部分成交场景后，再研究 `FCA006`、`FRL002/003`；其余 P2 观察组保留机制、复现需求与否决理由，网站允许展示“未通过/暂不交易”，不以通过数量作为成功指标。

相应 Python 模块边界应是 `features / labels / hypotheses / portfolio / execution / reports`，不能每个 ID 各写一套回测器。展示页面中，一个 idea 的最佳产出不是一条漂亮净值，而是：机制、适用时间尺度、当时可知输入、可执行标签、试验记录、净成本结果、与现有组合的增量，以及可重跑的 snapshot/run 标识。
