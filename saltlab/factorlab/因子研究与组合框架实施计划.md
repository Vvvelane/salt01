# 从经济学 idea 到可验证交易：Factor Lab 研究与组合框架实施计划

编写日期：2026-09-06。性质：研究设计与工程计划；未运行行情回测，文中的窗口、资金、成本及风控数值均为待验证的项目起点，不能解读为有效参数或收益结论。

## 1. 我的判断，以及这个项目最终要回答什么

建议把项目定位为“**面向个人期货研究的、可复现的多时间尺度因子与组合实验室**”。第一阶段主攻 30–120 个可交易分钟及明确的尾盘窗口，用 1min 数据研究、用 5min 做主要决策；同时保留一个日频趋势基准，防止把“更频繁观察市场”误当成“必须更频繁交易”。先做少量可解释实验，再做真实手数与共享资金组合，最后把完整证据链展示在 Recipe 网站。

你提到的横向与纵向，可以精确为两个问题：

1. **同一品种，什么信息在多长时间内兑现？** 谁可能推动价格，谁承接风险，为什么会持续或反转，什么情况下解释失效？形成期、预测期、持有期、决策频率和执行频率分别是多少？
2. **所有品种和策略一起运行，账户究竟持有什么风险？** 同一合约的多空如何合并，黑色/有色/能源等相关暴露如何限制，资金不足时如何取舍，短周期与长周期策略是否重复下注？

最终研究单位应当是：

`经济假设 × 当时可交易的品种/合约集合 × 市场状态 × 时间窗口 × 执行规则 × 组合规则`。

一个公式不是完整因子研究，一个正 IC 不是策略，一个单品种盈利曲线也不是可运行账户。58 个旧 ID 应作为 idea 档案保留，按经济机制合并；同一动量 idea 的均线、MACD、回归趋势是竞争实现，不能各算一份独立分散化收益。

## 2. 先把 58 个 idea 放到正确的位置

### 2.1 每个候选先选角色，再选公式

| 角色 | 预测/控制对象 | 典型候选 | 正确验证方式 |
|---|---|---|---|
| `alpha` 方向预测 | 可执行未来价格变化或相对收益 | 趋势、开盘信息、短期反转、截面动量 | 方向、分组收益、样本外净收益、成本承受力 |
| `state` 状态变量 | 某种 alpha 在什么情况下有效 | 异常成交量、OI 变化、趋势效率、时段 | 同一基础策略的条件增量；按同样资金/风险比较 |
| `risk` 风险估计 | 未来波动、尾部或相关性 | RV、ATR、半方差、低波动 | 风险预测误差、超限次数、目标波动跟踪和换手变化 |
| `execution` 执行约束 | 是否交易、能交易多少、成本多大 | 量额、非流动性、合约生命周期 | 未成交、参与率、成本敏感性、容量与资金利用率 |

例如，高波动不等于该做空，OI 增长不等于新多头占优势，成交量增长不等于未来涨价。期货未平仓合约同时对应多空，只有 OHLCV/OI 不能识别主动买方、卖方身份或“主力资金流入”。先写可检验的条件假设：**已出现的上涨，在成交活动异常时是否更持续？** 这比把两个量相乘后取 sign 更容易解释。

### 2.2 因子卡必须具备的 14 个字段

每个首批实验一份 TOML 配置和一份简短研究卡；原 ID 映射为 `source_factor_ids`，新 ID 例如 `ORB_CONT_V1`。

1. `mechanism`：经济/行为机制与可能的反方解释。
2. `role`：alpha/state/risk/execution；可多角色，但分别做实验。
3. `hypothesis`：预期方向、适用市场与可证伪条件。
4. `universe_policy`：历史当时上市、可交易、可承担整数手的品种/合约。
5. `input_capabilities`：字段、单位、时区、历史元数据及最晚可用时间。
6. `formation`：特征窗口；是否跨休市/夜盘/换月。
7. `decision_schedule`：明确到 session 或事件时间，而非泛称“日内”。
8. `horizons`：预注册预测窗口、时钟类型和主检验 horizon。
9. `transform`：标准化、缺失值、截面排序、训练拟合边界。
10. `execution`：订单发出、最早成交、滑点、成交失败、退出和超时。
11. `portfolio_role`：方向、共享风险预算、与现有信号的冲突规则。
12. `validation`：时间切分、对照、参数预算、稳健性和成本场景。
13. `lineage`：文献/项目假设、数据/代码/配置/运行版本。
14. `decision_log`：保留、拒绝、证据不足或阻塞及理由；失败试验也保留。

## 3. “做 x 分钟、y 日、z 周”应如何选择

### 3.1 五种时间不能混写

| 时间 | 含义 | 示例 |
|---|---|---|
| 数据粒度 | 原始记录精细程度 | 1min |
| 特征形成期 | 信息累计多长 | 当日开盘 30min、过去 20 日同一时段、过去 60 日收益 |
| 决策频率 | 何时重新决定目标仓位 | 每个完整 5min、每天一次、每周一次 |
| 预测 horizon | 用什么未来窗口评估信息 | 下一 30/60/120 可交易分钟或 5/20/60 日 |
| 实际持有期 | 真实进场到离场 | 最长 60min，也可能被 session 结束提前截断 |

1min 数据不要求 1min 交易。日频信息也不要求用日线 OHLC 撮合；可以在次个交易时段用 1min 仿真成交。用更多小 K 线增加样本行数，不等于增加独立经济样本。

### 3.2 从机制决定候选尺度

| 机制 | formation 起点 | 主研究 horizon 起点 | 适用解释与限制 |
|---|---|---|---|
| 开盘信息逐步吸收 | 当次开盘 15–30 可交易分钟 | 30/60/120min，或尾盘固定窗口 | 新信息可能延续，也可能已完全定价；日盘/夜盘不可混池 |
| 短期流动性冲击恢复 | 最近 15/30/60min，相对近期尺度标准化 | 15/30/60min | 新闻冲击可能继续，逆势持仓的尾部损失尤其重要 |
| 日内时段效应 | 同一 session/同一相对时段的历史分布 | 尾盘 20–30min 或固定事件窗口 | 研究的是时间结构，不是每天任意找一段涨跌 |
| 波动持续 | 过去 20 日同窗口与当日已发生 RV | 下一 30/60min；日频风险另估 | 预测未来方差，不预设未来收益符号 |
| 中慢趋势 | 20/60/120/252 交易日（先固定 60） | 5/20/60 日（先固定 20） | 长 lookback 的文献不能直接证明 30min 动量 |
| carry/库存相关代理 | 当日可见曲线，5/20 日平滑对照 | 5/20/60 日，周再平衡 | 期限结构不是分钟方向信号，不等于锁定套利收益 |
| 跨期/相对价值收敛 | 60–252 日稳定关系或相同到期生命周期 | 1/5/10/20 日，受半衰期和换月限制 | 残差 z-score 不是必然回归，需检验结构变化 |
| 月份季节性 | 多个完整年度、同季节同期限 | 数日到数周 | 年份才是主要独立样本单位，百万分钟也不能增加年份 |

这些是研究先验，不是最优参数。经典时间序列动量研究主要提供月度至年度尺度的证据；项目缩短到日内必须重新立假设。[Moskowitz、Ooi 与 Pedersen，2012](https://www.aqr.com/Insights/Research/Journal-Article/Time-Series-Momentum)。中国期货日内研究对部分品种发现首半小时可预测尾半小时，但中国原油研究也报告不同结果，所以不预设全品种共享同一个方向。[Jin 等，2020](https://onlinelibrary.wiley.com/doi/abs/10.1002/fut.22084)，[原油日内研究，2021](https://www.sciencedirect.com/science/article/pii/S0264999321000134)。

### 3.3 具体 apply：画 horizon 曲线，而不是事后挑最高 Sharpe

1. 每个机制先指定一个主 horizon 和最多两个邻近对照，避免 lookback×持有期×品种×阈值全网格。
2. 每个信号保存 `decision_time`、可成交 entry、各 horizon 的预定 exit；生成 raw price-change 标签、风险归一标签与带方向成本标签。
3. 按品种、年度、session、预先定义的市场状态估计条件均值、分位差和区块 bootstrap 区间。
4. 画“信号后累计边际收益/风险/费用”曲线。理想证据是相邻 horizon 均有一致方向，效果在某一范围趋于平稳，而不是只有 37min 一个尖峰。
5. 决定实际退出时，加入下一段边际收益、双边成本、占用资金和尾部风险；优先固定持有作为基准，之后仅测试一个可解释退出变体。
6. 只用训练/验证段选择 horizon，冻结后对完整未来测试段一次评价；不可在全样本衰减图上选 horizon 后称为样本外。

日内若距强制退出只剩 20min，不能把实际 20min 收益标成 60min。记录 `requested_horizon`、`actual_horizon`、`exit_reason=session_cutoff`；固定完整窗口统计和真实策略统计分别报告。

## 5. 让回测有意义：必须兑现的市场与执行语义

### 5.1 数据版本与“当时知道什么”是两条不同的轴

`catalog_revision` 和 Manifest/hash 用于回答“此次研究读了哪一版文件”；`available_at`、元数据生效时间和发布可得时间用于回答“交易时是否已经知道”。版本完整并不会自动消除前视偏差。

每次运行冻结：索引版本、每个被消费文件的 revision/hash、字段映射、session/calendar 版本、合约规则/费用版本、代码快照、lockfile、配置、随机种子及数据截止时间。若源系统只能保留当前物理路径，研究侧只为本次读取的分区保存不可变快照/内容寻址副本；**不能只记 hash，却在原文件被覆盖后仍声称可重跑旧版本**。不建第二个源行情目录扫描器。

### 5.2 五个时间字段与同边界事件顺序

所有 bar 都有 `bar_start < bar_end <= available_at`；信号需要 `max_input_available_at <= information_cutoff <= emitted_at <= decision_time`；订单成交需满足 `fill_time >= earliest_fill_time`。还必须定义同一时间戳事件先后，不能仅靠 `>=` 证明可执行。

- 零延迟 next-open 是研究代理：bar 收完→特征→决策→下单→下一 bar 撮合，明确 event phase。
- MVP 基准更保守：凡依赖刚结束 bar 的信号，**跳过该结束边界的即时 open**，选择严格晚于订单 ready time 的第一个 1min bar start；额外延迟 1min、5min 做敏感性。
- 数小时前已经发出的尾盘预定订单可以在预定边界进入；不需要凭空多等一根，但仍受交易状态和成交代理限制。
- 高低价仅在该分钟结束后可见。用收盘确认突破就不能再按本分钟突破价成交。

### 5.3 session、交易日和可交易分钟

使用 `Asia/Shanghai` 交易所时区与历史 calendar/session 版本，展示时可转用户时区；不能用电脑 Asia/Singapore 的自然日期替代交易日，尽管两地通常同为 UTC+8。

`session_id` 区分夜盘与日盘，`segment_id` 区分休息前后连续片段，`trading_date` 根据正式日历映射。周末、节假日前夜盘停开、历史交易时间调整不得简单按“21:00 后日期+1”。日盘开盘与包含夜盘的全交易日 open 也不是同一变量。交易所公布合约要素与交易时间，实际实施要使用对应历史生效版本。[上期所交易规则](https://edu.shfe.com.cn/TradingAssistant/RulesIntroduction/518.html)，[上期所交易时段资料](https://www.shfe.cn/specialtopic/investor/trade/)。

1min→5min 按 session segment 聚合，不能跨午休造 bar。开盘 30min 的累计时钟可跨该 session 的小休息，但具体实验若要求连续片段需另标。预定退出的 open 必须真实存在；缺失 bar 不补成交。

### 5.4 可交易合约、主力和换月

1. `product_id` 用于经济 idea；`contract_id` 用于订单与 PnL；连续指数只能用于明确构造的特征/展示。
2. 首批日内使用前一完整交易日可知的合约选择规则：历史有效合约中，以滞后成交/持仓排名及到期限制选一个；当天不因看到全日量而改主力。
3. 旧主力时间表若没有 `known_at/selection_cutoff`，可做历史描述，不能默认用其同日主力做可交易回测。需要独立产生并版本化 PIT 映射。
4. 日内平仓策略次日可换另一合约，但当天形成与交易必须同合约；不能用旧月早盘信号套到新月尾盘。
5. 隔夜策略换月是卖出旧月与买入新月两笔真实订单；各腿记录费用、滑点、失败和风险。旧月 100、新月 110，换到新月本身不会凭空赚 10。
6. 慢趋势使用同合约重叠报价链接的收益指数：换月后的新月收益用该新月上个基准时点价格作分母，避开合约价差跳跃；该时点必须已知。回调后的连续价格不做实际成交价。
7. 近交割禁入窗口和最迟退出取合约生命周期、适用客户规则及其历史版本；未具体确认前可用更早的工程缓冲，但标记为假设。

### 5.5 OHLCV 能支持的成交模型

| 场景 | MVP 处理 | 报告要求 |
|---|---|---|
| 普通入场/时间退出 | 预定下一可用 1min open 加方向不利滑点，整数手 | 标注 `bar_open_proxy`，不是成交重建 |
| 本分钟零成交或缺失 | 不成交；订单超时/取消按策略 TTL | 保留 `unfilled`，不能删除失败日 |
| 单边涨跌停锁住 | 保守拒绝受阻方向；退出失败继续持仓 | OHLC不能识别队列，不能强行平仓 |
| 非锁死但触及涨跌停 | 使用事前规则和单独保守场景 | 不以“volume>0”证明自己的订单能成交 |
| 止损/止盈同分钟触及 | 不利路径或区间上下界；首批不优化双障碍 | 无逐笔路径不声称知道先后 |
| 开盘穿过止损 | 按更差 open 加滑点，不按原止损价 | 不能把止损额当最大损失 |
| close 代理退出 | 仅作诊断，主基准收盘前预定 open 退出 | 收盘信号不可回填成交到同一 close |
| 多腿 | 后续做逐腿成交、剩余订单撤销、已成交腿卸载 | 已发生的 fill 不允许事后抹除 |

参与率存在一个容易忽略的边界：在未来一分钟成交量尚未知时，不能按该分钟最终 volume 决定 open 能成交几手。MVP 下单数量只用过去 20 日同时间段的量预测，给出参与率**估计**；事后超量作为容量风险标记。后续成交量受限模型在分钟结束后按该分钟成交量累计 partial fill，选择该分钟价格代理并明确时序，不能仍称全部在 open 成交。

零量/完整分钟锁板同样只有该分钟结束后才完全知道。MVP 固定采用“事先冻结订单、分钟结束确认”的 batch proxy：在 bar start 之前冻结候选订单与资金预留，bar 完整可得后由成交模型判定，保存 `effective_fill_time`（该 bar start 的价格代理时点）与 `fill_observed_at`（结果确认时点）。账户决策只能读取已确认成交；等待中的订单继续预留现金/保证金并按可能成交做风险上界检查，不能在 open 提前释放“未来会失败”的订单资金再转投其他标的。这个模型是分钟路径代理，不声称重建真实成交；订单后移一整分钟的替代价格场景同时报告。

### 5.6 成本、手数、权益、保证金

对线性人民币期货合约，手数 `q` 带方向、乘数 `m` 为每点每手人民币价值，真实 fill-price 账本：

`trade_pnl = q × m × (exit_fill_price - entry_fill_price) - open_fee - close_fee`。

成本模型支持按手、按金额、开仓/平今/平昨、经纪商加收和日期生效；不把目前费率复制回整个历史。按手费为 `abs(q)×fee_per_lot`，按金额费为 `abs(q)×m×fill_price×fee_rate`。平今/平昨按交易日持仓批次认定，不能按自然日。

基准和压力场景以每边 1/2/4 ticks 起步；这是滑点假设，不宣称由 1min 估出了真实 bid-ask。手续费使用可追溯规则或明确的待确认场景。先算一笔交易每手往返要吃掉几个 tick，再看预测的位移够不够覆盖；只展示 basis-point 成本会遮蔽不同乘数与最小跳动差异。

滑点已计入 fill price 时，权益不得再扣一次同额滑点；报告可用 reference-price 的毛 PnL减 implementation shortfall减手续费分解，与 fill-price PnL减手续费核对一致。

账户保持现金、已实现损益、未实现损益、冻结保证金及可用资金。保证金是资金占用，不是交易费用；期货收益分母是账户权益，不能无说明地用保证金作分母。日结算按历史结算价转换现金与持仓成本基础，转换不得创造额外 PnL。结算价格与未平仓盈亏的清算关系有交易所规则依据。[上期所交易规则](https://edu.shfe.com.cn/TradingAssistant/RulesIntroduction/518.html)。

缺结算价时可提供明确标注的 close-marked 研究账本，不能称其精确模拟结算和追加保证金。开平仓后逐笔/逐 bar 检查资金、最大手数和保证金；涨停无法止损时持续记账，并允许出现被动隔夜或强平失败状态。

## 6. 整体头寸平衡：从因子到唯一账户

### 6.1 分层决策与数学对象

```mermaid
flowchart LR
  I[经济机制与时间尺度] --> F[原始特征和状态]
  F --> A[各策略预期方向与目标风险]
  A --> B[按机制家族分配预算]
  B --> C[合约净额与相关性约束]
  C --> D[整数手及保证金约束]
  D --> E[订单与真实成交账本]
  E --> R[权益与风险归因]
  R --> C
```

每个子策略输出 `target_risk` 或风险归一化的 `forecast`，不直接各自假设拥有 100% 账户。组合层同时接收所有目标，输出唯一的每合约 `target_lots`。风险模型估计协方差与容量；执行层按实际成交更新账户，下一次决策面对的是实际仓位而不是理想仓位。

### 6.2 第一步：统一每手风险，杜绝等手数假分散

对于持有 h 的策略，滞后价格变化标准差为 `sigma_delta_price(i,h)`：

`one_lot_risk(i,h) = multiplier(i) × sigma_delta_price(i,h)`，单位元/手。

若子策略该品种目标标准差金额为 `B(i,k)`，连续目标手数可写为：

`q_star(i,k) = B(i,k) × clip(forecast(i,k),-1,1) / max(one_lot_risk(i,h), risk_floor(i))`。

`B`、risk floor、forecast calibration 只由训练样本和预设风险预算确定。低波动时不得无限放大；历史低波动刚好可能先于跳跃。

教学例：账户 100 万，某子策略给一个品种的单次预测标准差预算 1,000 元；乘数 10 元/点、60min 价格变化标准差 20 点，则每手风险 200 元，未考虑其他限制前为 5 手。另一个品种每手风险 800 元，最多约 1 手；这解释了为什么一手对一手不等风险。最终还要扣除组合相关性、成本、保证金及整数手限制。

波动预算与止损风险预算不同。若使用价格距离 d 的保护性止损，另一上限是 `floor(loss_budget/(m×d+estimated_roundtrip_cost_per_lot))`，但跳空和涨跌停可突破这个预算；不能将它称为保证最大损失。

### 6.3 第二步：按机制、时间尺度与品种三级分配

1. 单独研究期，每个策略使用相同风险尺度，先判断它自己是否有证据。
2. 组合初版只纳入通过研究门槛的家族。日内信息持续与日内恢复若都合格，先等家族风险预算；如果只有一个合格，不为凑“平衡”塞入不合格策略。
3. 家族内部多个变体共用预算。首尾动量和 ORB 先作 50/50 的家族内对照或只保留稳定代表，不因指标数多就扩大仓位。
4. 同一时间尺度内，各品种按滞后风险缩放，设集中度上限。不存在交易机会时预算留空，不自动重新放大剩余品种。
5. 日频趋势先作为独立基准，不在第一轮日内结果中偷偷加入隔夜收益。跨尺度组合阶段才预注册日内/慢周期预算，并在共同每日账户收益上评价。

给每个分钟策略各算一个年化波动，再把其权重直接与周频策略相加，是量纲不统一。统一用日账户收益估计家族层风险；用执行频率下的合约价格变化风险约束当前仓位，两层都保留。

### 6.4 第三步：净额、多空与相关性

`q_contract = sum_k(q_strategy_k)` 是真实订单前的同合约净额；同时保存子策略虚拟账本用于归因。例如一个信号希望 +5 手、另一个 -3 手，账户净 +2 手。不能把虚拟内部抵消也记成两笔交易费用；也不能将节省的费用不加说明地归给某一策略。用预先规定的按目标调整绝对量分摊规则，保证策略 PnL加净额效应等于账户 PnL。

“多空金额相等”不意味着市场、产业或尾部中性。时序趋势可以整体做多或做空；截面 alpha 可以加名义净敞口约束，但仍需看 sector、波动和 beta。跨期各腿名义净额近零，也仍有曲线风险和双腿保证金。

组合人民币损益方差：令 `D=diag(multiplier)`，`Sigma_deltaP` 为同一风险 horizon 的合约价格变化协方差，

`portfolio_var = q' D Sigma_deltaP D q`。

风险贡献 `RC_i = q_i × (D Sigma_deltaP D q)_i / sqrt(portfolio_var)` 可为负，这是对冲贡献；另显示绝对 standalone 风险和 gross exposure，防止“净风险很小”掩盖过大双腿。协方差只由过去数据估计；MVP 若先估同基准日收益协方差 `Sigma_r`，以决策时已知价格 P 转换 `Sigma_deltaP ≈ diag(P) Sigma_r diag(P)`，再乘合约乘数。此项是统一日风险/压力代理，不冒充30/60min预测；日内每手 sizing 使用对应 horizon 的价格变化尺度。不同休市时间的分钟不能靠填充零收益制造低相关；重叠 session 的分钟估计作为后续改进。方差为零或估计不可用时 RC 标记不可估，采用独立风险上界/保守减仓，不能除零或当作零风险。

### 6.5 首个仿真风控配置（全部为研究假设）

| 约束 | 初始场景 | 如何 apply |
|---|---|---|
| 账户年化目标波动 | 8%，对照 5%/12% | 仅依据过去日策略收益缩放；新策略历史不足先用保守固定预算 |
| 单品种 standalone 风险占比 | 不超过全部 standalone 风险预算的 20% | 按缩放前候选风险和统一预算上限检查，不用净 RC 抵消绕过 |
| 单产业组 standalone 风险占比 | 40% | 使用版本化产业分类；特殊相关组可追加 |
| 总保证金占权益 | 上限 30%，压力 20%/40% | 无明确组合优惠时各腿按保守 gross 保证金求和 |
| 总名义杠杆 | 上限 2 倍 | 与风险/保证金约束取更严格值 |
| 预测成交参与率 | 同时段预期 1min 成交量的 0.5%，对照 0.1%/1% | 只用滞后量预测下单上限，实际超量单列 |
| 日损失熔断 | 相对前交易日权益 -1% | 达阈值撤新开仓、安排可执行减仓；不能保证立即成交 |
| 回撤研究暂停线 | 历史峰值权益回撤 8% | 按既定规则进入 review，变更策略另开版本 |
| 日内退出 | session 结束前预留 5 可交易分钟 | 持仓建立时预排退出订单，使其在该边界可尝试成交；失败不伪造 flat |

这些数值只是用于让工程可执行。它们不是最优化目标，后续按账户规模、品种整数手、费用和压力情形验证可行性。MVP 不自动估计最优杠杆或凯利仓位。

### 6.6 约束冲突和执行顺序

优先次序固定为：已成交仓位风险→强制退出/降低风险→生命周期与交易状态→保证金/现金→品种/板块/相关性→目标预算→新开仓。遇到不满足整数手的目标，可以不交易，不强行凑一手。

先得到连续目标，再向零取整；**取整可能破坏对冲并提高净风险**，所以需要再次检查全部约束，并做确定性的减仓修复。修复失败则取消整组新开仓、保留合理减仓意图、输出原因。相同时间多个订单争用资金，用冻结的家族优先级/比例分配与稳定 ID 排序，不能随 DataFrame 行顺序改变结果。

暂不引入精确预期收益的均值方差优化。初版等家族风险+收缩协方差+硬约束更容易解释；待有稳定样本外预测，才尝试 `forecast benefit - risk penalty - turnover cost` 的约束优化，并与初版做同样成本对照。

## 7. 如何判断 idea 值不值得继续

### 7.1 三层证据，分别打分

| 层 | 回答的问题 | 产出 |
|---|---|---|
| 信息层 | signal 是否对预注册未来目标有增量信息？ | horizon 曲线、按品种 TS IC、按时点 CS IC、条件收益、区间估计 |
| 策略层 | 指定进出场和成本后能否形成稳定净收益？ | fills/trades/equity、成本敏感性、MAE/MFE、未成交和尾部损失 |
| 组合层 | 加入已有组合后是否改善账户而非重复暴露？ | 边际风险、净额收益、相关性、保证金峰值、规模敏感性 |

风险/状态/执行因子不要求自己有正收益 IC。RV 的标准是未来方差预测与风险控制；状态过滤器必须比同资金、同风险的未过滤策略有增量，不能只靠少交易降低波动就宣称 alpha。

### 7.2 样本切分的可执行协议

1. 在第一个统计结果出现前固定可用截止日、品种规则、主实验、参数预算和最终测试区间。
2. 如果过去历史已被反复查看，不能重新取名为 untouched holdout。登记 `previously_seen`，真正未见区间用于后续前向模拟。
3. 在足够历史下，最后连续 12 个月作为最终 holdout；此前做滚动训练 24 月、验证 6 月、测试 6 月的 walk-forward。所有品种按同一个真实时间边界切，不能随机打散分钟或让同一日期不同品种落进训练/测试两侧。
4. 每折训练/验证样本先满足 `label_available_at <= fold_freeze_time`，保存完整样本区间 `[decision_time, label_available_at]`，避免早盘决策、尾盘才产生标签被错误当作早盘已知。另对跨边界持仓/目标按 `[entry_time, exit_time]` 重叠进行 purge；固定分钟行数 `gap` 不能替代上述两项检查。
5. 日内标签的 purge 通常落在边界附近的交易日；20 日标签需要清除相应跨越区间。已有历史特征可用于测试预热，不能为了“隔离”错误丢掉当时已可知的过去价格。
6. 标准化、winsorize 阈值、状态分组、回归 beta、合约/家族选择和参数选择均在训练/验证完成，测试段不重调；在线滚动更新若允许，事先规定更新规则与已成熟标签边界。
7. 各折样本外收益按时间串联，同一天不能由多个重叠测试折重复贡献。最终 holdout 只在研究冻结后打开一次，若据此修改规则，之后只能称开发数据。

scikit-learn 的 `TimeSeriesSplit` 提供按顺序切分及样本数 gap，但项目的多品种、session 和可变持有期需要自定义 `PurgedWalkForward`。[官方文档](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)。

### 7.3 统计与防止挑结果

- 时间序列因子逐品种算相关/回归，再汇总；不能把所有品种价格层级和分钟混成一个 pooled IC。
- 截面因子在同一个决策时点按可得品种算 Rank IC；行业中性/全市场排序分别记录。小截面用连续 rank 或对称 top-k，不能五分位只有空腿却继续归一。
- 日内置信区间用整交易日区块，所有品种和策略同步抽同一组日期；跨日策略用覆盖持有期及相关结构的多日区块。禁止将相关分钟/重叠标签当 IID。
- 报告原始 bar 数、独立交易日数、有效信号数、交易次数、年度数，不让样本规模产生错觉。
- 所有窗口、阈值、方向、过滤器与失败运行进入 experiment ledger。首批方向实验各一个主规格、最多两个预注册窗口对照；退出和过滤器做顺序消融，不进行笛卡尔积搜索。
- 对多次尝试报告选择偏差敏感性；候选足够多时可附 DSR，并说明试验数量/相关性与非正态假设。DSR 或 PBO 不替代真正的未见样本，也不把输出解释成“盈利概率”。[Bailey 与 López de Prado，Deflated Sharpe Ratio](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)。

### 7.4 必须有的对照与压力测试

| 对照/压力 | 解决什么误判 |
|---|---|
| 零信号现金、同窗口恒定多/空 | 识别窗口市场漂移，避免把市场上涨归因于信号 |
| 同一信号无过滤 vs 加状态过滤 | 识别状态变量是否提供增量 |
| 固定风险 vs RV 缩放 | 分离选时与风险管理效果 |
| 只换一个邻近 formation/horizon | 检查参数尖峰，不无限搜参数 |
| 每边 1/2/4 ticks，手续费基准/加倍 | 计算成本吞噬与 break-even slippage |
| 信号后多等 1min/5min | 识别只靠边界成交的脆弱结果 |
| 分日盘/夜盘、年度、产业组 | 避免极少时期与品种贡献全部结果 |
| 去掉最佳品种/最佳月份后的诊断 | 识别集中贡献；不据此重新选择样本 |
| 前向已知换月 vs 事后主力映射诊断 | 量化映射造成的虚假收益 |
| 10/30/100 万元整数手账户 | 验证个人账户可交易性与分散化损失 |
| 涨跌停退出失败、单腿未平、相关性升高 | 保留策略最不愿面对的路径 |

### 7.5 晋级、失败和“证据不足”

硬门槛：无时间泄漏、账户账本恒等式成立、每笔成交可解释、可复现、保留全部成本与失败路径。硬门槛未满足时，任何收益结果都是 prototype。

研究门槛：主规格在样本外基础成本下有正的经济净效应，多个时间块/品种的证据不过度集中，邻近参数与延迟场景方向较稳定；组合加入后有增量而非重复。若置信区间跨零且成本压力下消失，应标 `inconclusive` 或 `rejected`，不以换个名字/方向重启免计试验次数。

没有统一适合所有策略的 Sharpe>2 或 IC>0.02 门槛。可预注册“至少 12 个月样本外、至少 200 笔/100 个独立交易日”作为日内项目的最低展示样本提示，但它不保证统计充分；慢策略与季节性需要不同样本单位。只在通过硬门槛后讨论收益。

## 8. carry、跨期与相对价值的后续路线

carry 的概念包含在其他条件维持不变假设下可事先度量的收益部分，未来价格变化仍有风险；它不是期货近远月差值可直接兑现为现金。[Koijen 等，Carry](https://www.aqr.com/Insights/Research/Journal-Article/Carry)。本项目第二阶段首先把曲线 carry 当跨品种预期收益排序变量，第三阶段才验证跨期结构交易。

对于近月 F1、远月 F2、年差 tau，可定义 `carry_proxy=(ln(F1)-ln(F2))/tau`，正号表示此定义下的 backwardation。用当时同一可得时点、可交易月份、真实到期年差。它可用于排序方向性单腿期货；若要做多近空远，必须另写关于**价差未来变化**的假设，不能由 carry>0 自动推导。

跨期/跨品种 PnL 使用 `sum_l(q_l×m_l×deltaP_l)-costs`。价差 z-score 的分母不是投入本金；两腿名义金额也不能简单相减作为收益分母。固定账户权益是统一报告基础。

对 `s=ln(PA)-beta ln(PB)`，若研究的是该残差方向，局部名义敞口应满足 B 腿名义约为 `-beta×A腿名义`；于是 `qB≈-beta×qA×mA×PA/(mB×PB)`，而非直接 qB=-beta qA。若用价格价差或物理加工关系，则按对应单位另推手数；beta 只能由过去拟合。

协整/半衰期在训练内估计并做稳定性检查。缓慢回归关系可以支持日级持有，不能只因用 1min 输入就缩成 5min 交易。多腿共同可得报价、非同步闭市、换月后残差重置、持仓期间 beta 更新引起的再对冲成本都必须显式实现。具体逐 ID 见组 3/4 附录。

## 9. 个人成长与求职展示怎样同时服务研究

### 9.1 提升市场敏感度的日常流程

每个交易日选择已预注册的 RB/CU/M 事件，投入 20–30 分钟复盘：

1. 先回放到信号出现的时刻，隐藏未来 K 线；写下继续/恢复/无判断及原因。
2. 对照程序当时可见的特征、合约、风险与可用资金，记录自己的判断是否使用了事后信息。
3. 放出后续 30/60min，比较预期、实际成交、MAE/MFE、成本与最终退出。
4. 给失败归因：假设错误、状态变化、成本、合约选择、执行或程序 bug。主观解释不能直接改生产规则。
5. 每周整理一个新假设，下周单独预注册；保持已冻结基准不变。

日内观察最有价值的产出是“预期—事实—解释”的记录，而不是增加交易次数。收盘复盘的人类备注存为 annotations，不参与当次回测特征；未来要将其结构化用于模型时，必须有真实生成时间。

### 9.2 网站应当展示研究过程和账户约束

沿用 Recipe 的 FastAPI、React、TypeScript、Vite，新增研究实验室页面。详细路由/API 与验收见[工程实施任务书](plans/engineering_workplan.md)。

核心演示故事：从一个 idea 点入→看到为何选 30/60min→查看冻结实验和样本切分→看到净收益及不确定性→点一笔交易回放当时可见信息→展示 +5/-3 手如何变成净 +2 手→更换资金/滑点**读取预计算场景**→解释保留或拒绝原因。

建议六块内容：idea 图谱、时间尺度实验、交易回放、组合风险、运行溯源、研究结论/失败档案。首屏突出“正在验证什么、证据到什么程度”，不只放漂亮 Sharpe 榜单。公众演示用合成/允许展示的聚合结果，清楚区分真实历史模拟、合成教学和前向观察。

### 9.3 可用于实习展示的真实交付

- 一份从经济机制到明确实验的研究报告，至少保留一个被拒绝的假设。
- 可复现 Python 包：稳定时间/合约/事件键、执行模拟、共享资金与审计产物。
- 一个能从研究概览追溯到单笔订单的交互式网站。
- 因果性和账本不变量测试；运行耗时/峰值内存等实际 benchmark。
- 5 分钟演示脚本、架构图、英文项目摘要及复现命令。

简历应写可证实的工程与研究规模、评估方法和产出，不写尚未测量的高收益或“实盘可用”。无盈利 alpha 但有严谨失败结论、可复现实验及正确账本，也构成完整项目。

## 10. 推进次序和完成标准

| 阶段 | 核心产出 | 放行条件 |
|---|---|---|
| 0：规格冻结 | idea 卡、时间/合约/账户合同、实验 ledger | 可用手工例子算出一次完整交易 |
| 1：最小可信引擎 | PIT 合约、1min/5min 时钟、订单/资金账本 | 合成边界用例与账本核对通过 |
| 2：首批证据 | 四个方向实验与两个组件的分层报告 | 不泄漏、带成本、含失败、样本外协议成立 |
| 3：唯一账户 | 净额、家族预算、整数手、风险/保证金约束 | 单策略与组合归因对账、压力场景可解释 |
| 4：网站展示 | Recipe 研究页、交易回放、场景比较、运行溯源 | 页面数字来自已验证 artifacts，不在浏览器重算策略 |
| 5：慢周期扩展 | 截面动量、carry、之后跨期/相对价值 | 所需规则/多腿能力到位，沿用同一账本 |
| 6：前向观察 | 固定策略逐日生成信号与模拟成交，至少 8–12 周 | 核对历史模拟与前向运行差异；此时仍不自动推导实盘授权 |

具体每项工程工作、输入输出、测试、命令与估时见任务书。第一天应做的是冻结时间/合约/风险口径和手工 golden case；第一个可展示页面应来自一条完整、可核对的实验链。
