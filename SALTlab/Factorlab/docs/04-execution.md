# 04 — Execution Policy（尚未冻结）

执行政策必须显式回答以下问题；草案不具备运行资格。

| 项目 | 必须冻结的内容 |
|---|---|
| 同 bar 执行 | 哪些输入已知、事件顺序与可用市场信息能证明该成交因果成立 |
| Fill price | 使用什么可观测价格/代理；买卖方向；tick 舍入；跳空和价差处理 |
| Latency | 各段延迟、单位、时间时钟、同边界事件顺序 |
| 订单生命周期 | 类型、有效期、部分成交、撤单、拒绝、排队、重试 |
| 可交易条件 | session、停牌、涨跌停、零成交/缺行、容量约束和已知数据限制 |
| 退出 | 到期、策略退出、保护性退出、强制退出失败如何继续记录 |
| 多腿 | 独立成交或同步代理、单腿失败、剩余风险、对冲和成本 |
| 仓位大小 | 决策时可知风险、合约乘数、手数舍入、保证金和资金限制 |
| 摩擦 | 手续费、滑点/价差、冲击、融资/现金收益口径，避免重复计费 |

完整 bar 的 OHLC 不能证明其中的路径顺序。high 和 low 同时触及止盈止损时，不得事后挑有利路径。必须声明更细数据、保守路径或不可判定；结果中记录处理方式。同理，触及某个价格不等于一定能成交。

same-bar 不是所有场景统一禁止，但利用 bar close 产生信号、却按该 bar open 成交违反因果性。只有事先存在的订单与足够证据支持的执行政策才能讨论同 bar 成交；本轮不实现任何一种政策。

连续合约价格不是可交割标的。执行必须记录具体合约身份；缺失 multiplier、tick、费用或执行语义应明确报错。不得默认 multiplier=1、cost=0 或“无限成交”。实验若刻意采用零成本诊断，必须显式配置并标为 gross/理想诊断。

NaCl 的 `Strategy Translation` 是候选假设。诸如 `BT_DAILY_FUTURES_V1（待定义）` 只保留为知识来源，不在代码中创建同名的假冻结政策。
