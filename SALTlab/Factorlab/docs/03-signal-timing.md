# 03 — Signal Timing

| 时间 | 含义 |
|---|---|
| `feature_time` | 特征实际使用的最新观察窗口结束时间；不是未经解释的 bar 标签 |
| `signal_available_time` | 输入完整到达且计算完成后，信号最早可用时间 |
| `decision_time` | 策略依据当时可知信息作决策的时间 |
| `earliest_executable_time` | 决策经过订单/系统延迟后最早具备执行资格的时间；不是保证成交时间 |

因果偏序：`feature_time ≤ signal_available_time ≤ decision_time ≤ earliest_executable_time ≤ actual_fill_time`。相等仅表达理论上可能；是否允许同时间事件和如何排序必须由政策冻结。时间字段统一带明确时区；源时间标签转换在适配层完成，不能混用 naive 与 aware 时间戳。

举例只用于解释：源标签 09:00 的 1min bar 覆盖 `[09:00, 09:01)`。使用完整 close/volume 的特征不能在 09:00 可用。即使理想计算在 09:01 完成，也不能自动假定获取恰好 09:01 的 open；同边界的数据到达、决策、订单进入市场先后仍需冻结。

必须分别记录：行情发布时间/传输延迟、计算延迟、决策调度、订单路由延迟。说明延迟按墙钟时间还是可交易事件计数。闭市、午休、夜盘、节假日和缺行不能通过简单行号 `shift(1)` 悄悄变成相同交易机会。

多腿信号需证明每个输入在同一决策时点可知，报价时点差在已规定容忍度内。不可把未来出现的某一腿报价回填到过去快照。

本轮不冻结 next-bar、same-bar、T+1、固定分钟数或 session 边界。后续每个实验必须选定定义并写出带具体时间的正例和反例。
