# 01 — 研究职责与产物

`Idea → Factor Construction → Experiment → Signal → Backtest → Evaluation` 是职责链，不表示 factor 必须可交易，也不表示 Card 已指定唯一策略。

| 层 | 输入 | 输出 | 禁止跨越的边界 |
|---|---|---|---|
| Idea | NaCl JSON + 来源原文 | 经济机制、可证伪假设、竞争/组合关系 | 不把文献结论当成本地已验证事实 |
| Factor | 原始行情 + 过去可知的参数 | 特征值、所用信息截止时间、可用时间、有效性原因 | 不使用未来收益、不调用账本、不决定成交 |
| Experiment | Idea/因子版本 + 数据范围 | 样本划分、参数、对照、评价目标、执行政策引用 | 不依据最终测试期结果反复改方向/阈值 |
| Signal | 特征 + 冻结映射 | 方向/强度、四时间字段、失效原因 | 信号不是订单、fill 或实际 position |
| Backtest | 信号 + 数据 + 已冻结政策 | 决策、订单生命周期、fill、拒绝/失败原因 | 不在引擎内部悄悄改造因子 |
| Accounting | fill + 合约单位 + 估值事件 | 仓位、费用、现金、权益及对账 | 不从 signal 推导已成交仓位 |
| Evaluation | 因子/独立标签 或 已对账回测产物 | 信息检验 或 可执行净收益证据，明确区分 | 不将预测标签收益直接称为策略 PnL |

实验配置引用稳定的 `factor_id`、因子代码版本、registry hash、数据快照指纹和政策版本。配置中未定义的字段保持 `null`；不把“缺失”解释成零延迟、零成本或无限流动性。

组合 Idea 必须给出组件依赖和各自可用时间；概念关系图不是执行依赖 DAG。特征归一化、样本选择、参数拟合分别注明 fit 窗口。数据加载和特征计算可复用，实验配置承担研究选择。

运行产物放入 `runs/<run_id>/`：manifest、原始配置、特征/标签/信号、订单/fill、账本/对账、评价、日志。只有未来各阶段实际执行后才记录完成状态；本阶段不生成虚假的 backtest 结果。
